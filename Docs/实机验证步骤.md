# 实机验证步骤

## 0. 构建与侧载

先在 Mac 执行构建和模拟器测试。将 IPA 通过 SideStore 安装为独立应用；确认没有覆盖 Erosion 或 AirCard-iOS。诊断中确认系统版本与所选引擎；worse_query 需要有效的 Pawster.WQ 应用组。

## 1. 只读验证（首先执行）

1. 保留现有壁纸作为对照，启动 LocalDevVPN 并解锁设备。
2. 导入有效配对文件，点击“自动查询并只读验证路径”。
3. 观察界面是否保持响应，确认返回的是当前容器，日志包含查询来源、xattr 与元数据状态、存储版本和提供组件数量。
4. 当前历史线索是 `/var/mobile/Containers/Data/Application/E7A3AB7B-F016-4CD1-ACC7-16A6EDB58C2A`，实际结果以新查询为准。
5. 用关闭 VPN、失效配对文件测试失败提示、35 秒超时与取消。失败不应清空手动填写的路径，也不能开启写入。

到此不应出现 PosterBoard 内容变化。若身份核验、授权或结构检查失败，导出诊断，停止后续注入。

## 2. 本机配对与引导小窗（iOS 27）

1. 点击“开始本机配对”，允许本地网络访问；确认显示准确步骤和工具名称。
2. 在引导卡片可见时点击“开启配对引导小窗”。进入设置指定页面，观察是否持续显示。
3. 选择“与 Pawster 配对”，确认六位配对码来自当前会话，能够在后台更新。
4. 分别测试成功、取消、180 秒超时和用户关闭小窗。确认广播和保活停止，PIN 消失，旧回调不会更新新会话。
5. 关闭画中画功能后重试，确认 App 内步骤与 PIN 仍可查看，不伪报小窗成功。

不能只凭“小窗显示成功”判定后台协议继续运行，必须实际完成配对并成功查询路径。

## 3. 注入验证

1. 导入已知可用的 StudyFriends-0.4.1-UIRegistration-Control.tendies。
2. 预览应识别 1 个描述文件；目标目录数量取决于设备现存的新旧 Collections 组件数量。
3. 检查计划未包含旧壁纸 UUID、数据库、整容器替换和全局偏好路径，确认后注入。
4. 检查记录为“文件已校验”，原有壁纸目录与内容保持一致。
5. 打开系统壁纸界面检查新壁纸。需要时单独执行“备份并刷新注册”，关闭并重新打开壁纸界面。
6. 分别记录：文件成功、偏好刷新成功、图库出现、锁屏使用及动画效果。未出现时保留日志，不执行 Reset。

## 4. 取消和恢复

1. 写入前取消，确认没有目标内容变化。
2. 写入过程中取消，检查记录标为部分完成；撤回后仅本次新增内容被删除。
3. 实验设备上模拟应用被系统终止，重开后检查未完成记录，验证 stage / moving / written 状态恢复。
4. 在测试副本中修改本次注入的文件后执行撤回，应停止删除并明确提示外部更改。
5. 刷新后再修改偏好文件，撤回应停止覆盖该文件。
6. 已有同名目标即使内容与源包完全相同，也不能被覆盖或在撤回时删除。

## 5. 旧系统

按同样步骤在 iOS 26.0–26.6.1 对应设备使用 bad_query 验证。iOS 27.0 beta 4 必须核实完整构建号，再勾选兼容选项。不能以新系统测试代替旧引擎实测。
