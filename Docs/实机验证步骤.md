# 实机验证步骤

## 待验证：重大风险确认与免费提示（本地未构建）

1. 首次启动查看红色风险标题和要点，确认明确说明系统/壁纸数据损坏、数据丢失、启动故障、恢复系统可能清除数据及备份不能保证恢复。分别检查中英文、浅深色、大字号及 VoiceOver，风险信息不能只靠颜色表达。
2. 风险确认默认未勾选，同意按钮不可用；仅勾选不开放操作。只有勾选并点击“同意协议、确认风险并启用”后，才可进入导入、配对、查询、注入、注册/撤回和系统刷新流程。验证这些门禁时先使用合成文件及模拟会话，不为验证同意逻辑而写入真实系统壁纸。
3. 选择“暂不启用”、重新打开说明和重新启动 App，均不得被视为同意。重新打开未同意的说明时确认项应恢复未勾选；本地已有内容和数据清理入口仍可使用。
4. 使用旧版同意记录升级到本地政策版本 2026-11-13.3 后，必须重新确认；只有政策同意版本或只有风险确认版本均不能开放功能。接受新政策后，配对处理仍需单独授权，不自动沿用过期授权。
5. 撤回同意后核对政策、风险确认及配对处理授权记录均清除，自动刷新关闭，新增操作重新锁定；导入包、事务记录和系统已有壁纸不应因此被删除。
6. 首次说明和设置都能查看免费提示，官方链接打开 latest Release。不得出现付费激活、支付或会员请求，也不将全部第三方收费再分发一概描述为违法。受控缺失/空白政策资源测试应使同意按钮保持禁用。

本项仅已完成本地源码与文案修改；遵照本轮要求不提交、不推送、不编译或打包，以上交互仍待获准后验证。

## 0. 构建与侧载

使用 GitHub Actions 已通过构建和测试的 IPA，或先在 Mac 自行构建测试。将 IPA 通过 SideStore 安装为独立应用；确认没有覆盖 Erosion 或 AirCard-iOS。诊断中确认系统版本与所选引擎；worse_query 需要有效的 Pawster.WQ 应用组。

正式下载见[最新 Release](https://github.com/GotTal/Pawster/releases/latest)，构建与包内资源证据见[验证记录](验证记录.md)及对应工作流。诊断日志默认关闭，排错前请在“设置 → 偏好”选择保留条数。使用同一Bundle ID会覆盖此前Pawster测试/正式安装，不能同时保留两份。

## 1. 只读验证（首先执行）

1. 保留现有壁纸作为对照，启动 LocalDevVPN 并解锁设备。
2. 导入有效配对文件，点击“查询路径”。
3. 观察界面是否保持响应，确认返回的是当前容器，日志包含查询来源、xattr 与元数据状态、存储版本和提供组件数量。
4. 使用本机最新查询得到的 PosterBoard 容器根目录，不要复用其他设备或旧安装的容器 UUID。
5. 用关闭 VPN、失效配对文件测试失败提示、35 秒超时与取消。失败不应清空手动填写的路径，也不能开启写入。

到此不应出现 PosterBoard 内容变化。若身份核验、授权或结构检查失败，导出诊断，停止后续注入。

## 2. 本机配对与引导小窗（iOS 27）

1. 点击“开始本机配对”，允许本地网络访问；确认显示准确步骤和工具名称。
2. 留在连接页，确认 App 内引导预览能看到设置路径和等待配对码文字，再离开 App 前往设置；小窗应自动弹出，不再提供手动开窗按钮。若系统未允许自动画中画，返回 App 查看配对码与提示。
3. 选择“与 Pawster 配对”，确认六位配对码来自当前会话，能够在后台更新。
4. 完成配对：小窗应立即清除 PIN，显示“配对成功”，保留约 3 秒后自动关闭并结束后台音频保活；App 内应显示配对文件已保存。
5. 分别测试取消、180 秒超时和手动关闭系统小窗。失败与超时也应清除 PIN 并关闭小窗；手动关闭小窗不取消当前配对，返回 App 仍可查看配对码。快速开始新会话时，旧会话计时器不能关闭新的小窗。
6. 关闭画中画功能后重试，确认 App 内步骤与 PIN 仍可查看，不伪报小窗成功。

不能只凭“小窗显示成功”判定后台协议继续运行，必须实际完成配对并成功查询路径。

## 3. 注入验证

1. 导入已知可用的 StudyFriends-0.4.1-UIRegistration-Control.tendies。
2. 预览应识别 1 个描述文件；目标目录数量取决于设备现存的新旧 Collections 组件数量。
3. 检查计划未包含旧壁纸 UUID、数据库、整容器替换和全局偏好路径，确认后注入。
4. 检查记录为“文件已校验”，原有壁纸目录与内容保持一致。
5. 打开系统壁纸界面检查新壁纸。需要时单独执行“备份并刷新注册”，关闭并重新打开壁纸界面。
6. 分别记录：文件成功、偏好刷新成功、图库出现、锁屏使用及动画效果。未出现时保留日志，不执行 Reset。

## NeoSpring（已通过编译和控制测试，待实机验证）

以下交互已包含在test.9、待实机确认：主按钮改为“预览并注入壁纸”，确认后才写入。刷新系统界面是下方的次要操作；每次手动点击须确认说明。自动选项首次勾选显示风险说明，取消不能开启，确认只保存选择且不会立即刷新；此后写入并校验成功直接自动刷新，不逐次询问。此前未确认过新版说明的自动选项会先关闭，需重新勾选确认。测试在待确认时切后台、取消、快速重试及再次开启；不得由旧回调误开启或启动刷新。

1. 首次进入壁纸页，“自动 NeoSpring”应未勾选；勾选后重开 App 检查选择是否保留。
2. 点击“NeoSpring”测试手动刷新；这是系统界面重载请求，不能只凭 WebKit 结束判断壁纸已显示。
3. 未勾选自动项时，成功写入后不触发 NeoSpring。勾选后，确认本次全部文件已写入、校验和记录完成，才触发一次。
4. 写入失败、取消和重复点击时，不能额外触发 NeoSpring；失败记录应继续保留。
5. 测试 NeoSpring 取消、15 秒超时、切到后台、WebKit 加载失败及快速重试，确认遮罩关闭、旧回调不影响新会话，原有壁纸记录仍能撤回。

## 4. 取消和恢复

1. 写入前取消，确认没有目标内容变化。
2. 写入过程中取消，检查记录标为部分完成；撤回后仅本次新增内容被删除。
3. 实验设备上模拟应用被系统终止，重开后检查未完成记录，验证 stage / moving / written 状态恢复。
4. 在测试副本中修改本次注入的文件后执行撤回，应停止删除并明确提示外部更改。
5. 刷新后再修改偏好文件，撤回应停止覆盖该文件。
6. 已有同名目标即使内容与源包完全相同，也不能被覆盖或在撤回时删除。

## 5. 旧系统

按同样步骤在 iOS 26.0–26.6.1 对应设备分别选择 worse_query 和 bad_query 验证；默认应为 worse_query。iOS 27.0 beta 4 只有完整构建号为 24A5390f 才显示双引擎。不能以新系统测试代替旧引擎实测。

## 设置、关于及隐私（已通过编译和资源测试，待实机验证）

1. 首次进入能离线阅读协议与隐私政策，邮箱为 xkstudio@icloud.com。选择“暂不启用”后仍能浏览已有本地包、记录和法律文件，可左划删除包、清除日志、移除凭据；不得开始导入、系统查询或写入。
2. 同意后首次导入配对文件、开始配对或用已有凭据查询时，须再显示配对处理提示。取消不开始对应操作；单独同意后才继续。政策版本更新后应重新询问。
3. 底部只有“壁纸 / 连接 / 设置”。记录、撤回与注册刷新入口位于设置内，原有记录继续可见。“关于”位于设置末尾，核对版本、开发者、GitHub、邮箱、开源声明及全文入口。
4. 断网打开全部法律与许可文档，包含长篇 Rust 许可文本，检查可滚动、可复制且无持续卡顿。检查小屏、大字号及浅色/深色外观。
5. 切换外观与日志条数，重开后保存选择。日志默认不记录；开启后只保留选择的最大条数，进程重开不恢复内存日志。准备并清除日志后，内存及本工具临时导出应消失，操作记录与备份仍在。
6. 无操作进行时移除凭据，检查需要重新导入/配对；Packs、Transactions、外部原包和系统壁纸不变。配对或写入进行时，相关清理与撤回授权按钮禁用。
7. 单独撤回配对处理授权后，下一次系统连接重新提示，凭据仍保留供用户另行删除。撤回整体同意后，自动 NeoSpring 关闭、当前日志和临时导出清除，新增操作停用；本地浏览、删除及关于仍可用。

## 配对文件及成功状态（test.9 已打包，待实机验证）

1. 未配置时显示“尚未配置”，入口为“导入配对文件”和“开始本机配对”。已有文件但尚未同意配对处理时，仅检查存在性，显示绿色“已保存”；授权后检查支持格式并显示“配对文件已就绪”。重开 App 应恢复对应状态，入口为“替换配对文件”和“重新配对”，不再提示“尚未开始配对”。
2. 导入后显示文件已导入及查询路径提示。该状态只表示本地文件结构符合支持的格式，不代表当前设备已接受凭据；过期或其他设备的文件仍须通过实际只读连接验证。
3. 本次本机配对成功且文件保存完成后，页面显示绿色勾选和“配对成功，配对文件已保存。”，小窗仍按原流程显示成功后关闭。重开 App 回到文件就绪状态，不虚报新的配对已经完成。
4. 重新配对时不能继续显示上次的成功标志；取消、超时或失败后原文件应保留，并显示保留提示。原文件仍可用于只读路径查询。不得重置系统壁纸。
5. 在应用测试目录放入空文件、无关 plist、损坏文件或超过1 MB的文件，授权检查后显示橙色“配对文件不可用”及替换提示，不能启用依赖凭据的查询；未授权时只能显示已保存，不读取内容。尝试导入这些文件不得覆盖原有效文件。
6. 删除本工具凭据后重新进入连接页，恢复导入及开始配对入口。分别检查中英文、大字号、浅色和深色；本地格式检查不发起网络连接、不输出密钥。12项 PairingCredentialsTests 已通过test.9的Xcode测试，实际设备信任仍需实机确认。

## 配对小窗关闭（test.9 已打包，待实机验证）

1. 在设置中完成配对，保持不切回 App：成功文字显示约3秒后，应结束画中画和保活音频，不留下悬浮的“直播”窗口。系统关闭动画完成前应保留成功帧，避免突然变黑。
2. 成功提示期间立即切回 App，以及成功后等待10秒再切回 App，分别检查悬浮窗和页面顶部的预览均被清理，连接页仍保留明确的成功状态。前台清理不依赖后台计时任务恢复。
3. 配对尚未完成时返回 App，应保留配对过程及当前验证码，不能被前台清理逻辑提前终止。取消、超时和失败后按结束流程关闭，不能残留验证码。
4. 测试点击画中画恢复按钮、手动关闭窗口、窗口被其他画中画暂时挂起，以及配对成功恰逢画中画启动动画的情况。系统延迟进入画中画后仍应收到停止请求；手动关闭成功窗口也应清除应用内预览。
5. 上一小窗仍在关闭时重新开始配对，旧控制器回调、旧的3秒计时和停止重试不得关闭新会话。新会话应重新显示和更新自己的验证码，前台/后台切换仍能正常引导。
6. 新增可注入的画中画生命周期测试覆盖真实系统开关以外的状态分支：等待关闭确认、返回前台、启动延迟、关闭回调缺失、挂起状态、成功帧手动关闭及新会话隔离。停止重试有次数上限，之后断开内容源并释放保活；若该兜底被触发会显示关闭异常说明。包含9项新增用例的14项小窗测试已在test.9的Xcode构建通过，仍须在 iPhone18,1 实测以上行为。

## 本地 VPN 状态和覆盖地址（test.9 已打包，待实机验证）

1. 新版协议版本为2026-11-12.2，新增本机接口与路由检查告知。同意前不执行状态监测；同意后前台约2秒更新，返回后台停止。
2. LocalDevVPN断开时显示未连接，Iface IP为“—”；连接后检查Iface IP和Peer IP与实际配置一致。未知/读取失败应显示尚未检测/无法检测，不得当作已连接。
3. 用普通Wi-Fi或无关VPN验证，只有到Peer的路由确实采用活动隧道时才能显示已连接。此徽章不证明VPN提供者身份或RSD可用，仍需配对及只读路径查询。
4. 输入有效私网IPv4并应用，重开保留；无效地址、端口、CIDR、前导零、公网或回环地址不能覆盖原值。恢复自动后重开不得恢复旧的网关覆盖。手动覆盖不回退到默认对端；配对、查询或写入期间不能修改。
5. 快速更换覆盖地址、切后台或撤回同意，旧的异步检测不得覆盖新选择。用LocalVPNTests的注入式接口数据验证此行为，不向实际对端发送测试数据。
6. 原生查询新增兼容旧入口的策略接口，后续Mac构建需重新生成Core库（CI已包含该步骤），不能沿用缺少新符号的旧xcframework。检查自动模式的默认候选和手动模式的严格地址选择。

## 首次使用指引（test.9 已打包，待实机验证）

1. 清空应用测试沙盒或使用全新安装，先出现使用说明；未同意前不自动配对或检测网络。同意后自动切到连接页的四步指引。点击稍后设置，下一次启动不强制弹出，连接页与设置的工具分区可继续打开。
2. 安装步骤的下载入口应打开 App Store 的 LocalDevVPN（ID 6755608044，Coxson Engineering LLC），项目入口为 jkcoxson/LocalDevVPN。已安装或已有可用本地 VPN 时可直接进入连接检查，不把打开商店当作安装完成。
3. 打开 LocalDevVPN 仅唤起应用，不自动添加配置或连接。按指引点击 Connect，在系统提示中允许添加 VPN 配置，完成后返回。未检测到活动隧道通向 Peer 时不能进入下一步；切后台或重启后重新检测，不能用保存的假状态跳过。自定义 Peer 可选择稍后设置后回连接页调整。
4. 开发者模式步骤说明系统设置路径、重启及重启后的再次开启确认。按钮实际打开本 App 的系统设置，说明须让用户先返回设置首页。检查“找不到开发者模式”中的 Apple 官方说明。此开关无法由 App 自动读取或开启，只有用户勾选已开启确认后才进入配对步骤。
5. 在开发者模式步骤退出 App 或重启手机，重新打开应恢复该步骤；重新连接 LocalDevVPN 后继续。指引状态只保存步骤和标记，不保存验证码、不替代政策同意或配对处理授权。
6. iOS 27 测试首次本机配对：点击开始时先经过既有配对授权，取消授权不能启动服务；允许本地网络，按系统路径点击与 Pawster 配对，输入实时六位码。小窗仍由外层原生预览提供，离开 App 后自动启动，成功后自动关闭，返回 App 后状态一致。
7. iOS 26 应展示导入配对文件的分支，没有可点击的本机配对按钮。检查已有 SideStore 文件路径提示、导入成功/失败、取消文件选择、已有凭据授权使用等流程。文件格式就绪不能被标成新配对握手成功，实际设备信任仍须下一步的只读连接验证。
8. 配对取消、失败、超时和 VPN 断开时，状态及原文件保留提示正确；正在配对时上一步与稍后设置按钮禁用，仍能取消配对和打开系统设置。完成设置需当前 VPN 路由可用、凭据就绪及开发者模式确认；成功后恢复连接页，并提示使用自动查询且只读验证路径。不自动注入或修改原有壁纸。
9. 完成后重启不再自动显示指引；从连接或设置可重新查看并回到前一步。测试中英文、VoiceOver、大字号和深浅色。11项 SetupProgressTests 已通过test.9的Xcode构建，仍需上述实机流程验收。

## 动态背景（test.9 已打包，待实机验证）

1. 壁纸、连接、设置及记录/诊断页面采用代码绘制的薄荷青与淡蓝光晕、淡网格和少量线路。观察至少一分钟，光晕应非常缓慢移动，节点仅轻微明暗变化；卡片、文字、按钮保持清晰，不出现抢眼的闪烁或扫光。
2. 检查浅色、深色、小屏、大字号、横屏和 iPad。列表滚动、包选择、左划删除、超链接和按钮点击不受装饰层阻挡；背景不进入 VoiceOver 的朗读顺序。
3. 在设置的偏好设置中关闭“动态背景”，背景应停留为静态装饰；重开后开关选择保留。再次开启恢复缓慢变化，中英文开关标题正确。
4. 系统启用“减少动态效果”或低电量模式时暂停动画；“增强对比度”时使用纯系统背景。切换这些设置后无需重启 App。返回后台、切到其他标签或进入其他页面时停止该页面的时间线更新。
